# Provider evidence contract

Circle is the only implemented payment provider. Paid-service execution supports `exact` and `GatewayWalletBatched` x402 on Arc Testnet. METRON binds the service URL, HTTP method, inspected seller, scheme, maximum amount, accepted chain, and canonical request-body hash into an approved Spend Intent. It passes that same method and body to Circle CLI `services pay`, then verifies direct transfers through Circle's transaction history or Gateway transfers through Circle's x402 transfer API. A Gateway receipt ID alone does not confirm payment: only its authoritative record with matching payer, seller, network, USDC amount, and `confirmed` or `completed` status can create a Payment Entry. `received` and `batched` remain `UNKNOWN` for later reconciliation; METRON never retries automatically.

Normalized Payment Evidence contains provider identity, provider reference, direction, amount in integer atomic units, currency, authoritative status, payer/payee, settlement reference, optional chain/transaction hash, observation time, and a SHA-256 hash of the raw provider response. Only confirmed Circle history that matches the approved wallet, seller, chain, scheme, currency, direction, and amount can create a Payment Entry and balanced Journal Entry.

A future provider must expose its identity/capabilities, normalize evidence to this shape, query current status from its authoritative source, provide a stable unique provider reference, and preserve ambiguous results. Payment Entries and Journal Entries remain provider-independent. Do not add a registry or provider factory for a second implementation.
